# Calibration release controls

Candidate registration, scientific approval and release selection are distinct records. Migration 0010 and `model-releases.mjs` implement an append-only release decision history scoped to bank version, course and unit. A release references an immutable approval; a null approval withdraws calibrated use for future sessions. Restoring an earlier approval creates another revision rather than rewriting history.

Each write supplies the predecessor the instructor reviewed. Database triggers reject stale predecessors, skipped revisions and approval scope mismatches. The decision and audit event commit in one transaction. Identical retries return their original receipt even when newer decisions exist; they never restore an old state. Approval content is revalidated against its archived bank before a new non-null release decision is accepted.

Verification: six registry test groups pass, including concurrent identical requests, competing withdrawals, restoration, stale direct SQL writes, scope mismatches, immutable history and audit counts. The complete economics suite has 192 passing tests; bank audit has no errors or warnings.

Session creation now pins the current release map in the same transaction as the session, including an explicitly empty map when no calibration is released. Both self-directed and assigned assessments validate filtered calibrated-family capacity before creating a session. A release changed between validation and insertion aborts the entire transaction. Self-directed assessment lengths are capped at 36 or the available distinct family count; assignment lengths remain instructor-specified. Practice does not use calibration pins. Tests verify rollback on a changed release, preservation after withdrawal, calibrated presentation parameters, and rejection of inadequate pools without consuming a session. The complete suite has 194 passing tests.

Instructor routes now expose the current scoped release and authenticated release decisions. Package detail and directory responses report actual activation state. The review panel provides explicit approval selection or withdrawal, a required rationale, confirmation, and the predecessor identity used for stale-write protection. Evidence and rationale render as text. Route tests verify student access rejection, release/withdrawal status and stale-write errors; DOM tests verify confirmation, scope matching and error recovery. The suite has 197 passing tests. No real model has been released. Next: authenticated browser verification, release-history browsing and deployment checks. Existing session pins must remain immutable; legacy unpinned sessions stay provisional. A release is not evidence that a model is scientifically defensible: the independent review and calibration evidence gates remain mandatory.
