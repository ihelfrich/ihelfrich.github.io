# Float64 tank kernel bookkeeping: preregistered contract

This pass moves projection bookkeeping and timestep extrema scans from JavaScript to the existing Float64 WebAssembly module. It changes no physical equation, boundary condition, pressure eigenvalue, transform, scalar flux, or stability bound. The JavaScript `Tank3D.project`, `divergence`, and `substepLimit` loops remain the independent reference. The spectral pressure solve stays between the preparation and finishing helpers.

`projectionPrepare(t)` zeros normal face velocities at all six closed walls; computes cell divergence in the existing x, then y, then z arithmetic order; accumulates `mean += rhs[d] / n` in linear cell order; and replaces each `rhs[d]` with `-rhs[d] + mean`. `projectionFinish(t)` subtracts the three existing face gradients of `phi`, recomputes divergence in that same order, and returns `sqrt(sum(rhs[d] * rhs[d]) / n)` with the linear-order sum. The wrapper sets `t.projectionResidual` and retains the existing nonfinite or greater-than-1e-6 rejection. It may not hide a failed projection or change the closed-wall pressure operator.

`extrema(t)` scans all u faces, then v faces, then w faces, then cell salinity, returning `{umax,vmax,wmax,smin,smax}`. The JavaScript caller retains the Courant, buoyancy, diffusion and substep-count expressions. Nonfinite input must produce a nonfinite result or a clear error, never a finite safe timestep. Output buffers are allocated once per kernel instance.

Before implementation, the acceptance checks are: (1) missing wrapper helpers fail a focused unit test; (2) deterministic arbitrary finite face fields, including nonzero wall faces, on 16³, 32×16×32, and 64×32×16 grids produce prepared `rhs` and final velocity components within 1e-15 absolute error against the independent JavaScript loops when both use the same spectral solve; (3) an already projected field remains projected within 1e-8 s⁻¹, and the pressure residual gate still rejects a deliberately nonfinite solve; (4) extrema match independent JavaScript scans exactly for finite seeded fields and reject NaN/Infinity rather than quietly accepting a timestep; and (5) one complete 16³ reference step retains the existing <1e-11 m/s and concentration agreement. These are numerical and safety gates, not performance claims.

Measure median helper times on 64³ after warmup; only retain the optimization if combined projection bookkeeping and extrema are faster in the actual browser worker or representative WebAssembly runtime. SIMD may be tried only after ordinary Float64 parity passes, with a measured speedup and the same numerical gates. No fast-math or reassociation is permitted. Public WebAssembly artifacts and verification records are regenerated by the parent after the source is frozen.
